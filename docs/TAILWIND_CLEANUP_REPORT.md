### 2.2 Inconsistent Class Ordering

**Issue:** Components don't consistently follow the class ordering convention.

**Convention (from .cursorrules):**

1. Position → `absolute`, `fixed`, `relative`, `sticky`
2. Display → `flex`, `grid`, `block`, `inline-block`
3. Sizing → `w-*`, `h-*`, `max-w-*`, `min-h-*`
4. Spacing → `p-*`, `m-*`, `gap-*`, `space-*`
5. Typography → `text-*`, `font-*`, `leading-*`, `tracking-*`
6. Colors → `bg-*`, `text-*`, `border-*`
7. Borders → `border`, `rounded-*`, `border-*`
8. Effects → `shadow-*`, `backdrop-blur-*`, `opacity-*`
9. States → `hover:`, `focus:`, `active:`, `disabled:`

**Examples of Inconsistency:**

**Dashboard.tsx (Line 512):**

```tsx
// ❌ Current: Spacing before display
className = 'flex items-center gap-2 px-6 py-3.5 bg-gradient-to-br...';

// ✅ Should be: Display before spacing
className = 'flex items-center gap-2 bg-gradient-to-br px-6 py-3.5...';
```

**Modal.tsx (Line 49):**

```tsx
// ❌ Current: Effects before colors
className =
  '... backdrop-blur-[20px] backdrop-saturate-[180%] border border-white/18 ...';

// ✅ Should be: Colors before effects
className =
  '... border border-white/18 backdrop-blur-[20px] backdrop-saturate-[180%] ...';
```

**Action Items:**

- [ ] Create ESLint rule for class ordering (using `eslint-plugin-tailwindcss`)
- [ ] Run automated fix across all components
- [ ] Add to pre-commit hook
